## Theory Notes

Understanding The Linux Filesystem Layout

Linux is not just a collection of random folders.

It has a standard structure that helps engineers know where to look for programs, configuration, logs, user files, temporary files, and system information. Once you understand that structure, Linux starts to feel less mysterious.

This lab focuses on the filesystem hierarchy: the layout of important directories and why they exist.

---

Why The Filesystem Layout Matters

When something breaks on a Linux system, one of the first questions is usually: where should I look?

Application logs may be under `/var/log`. System configuration is often under `/etc`. User files usually live under `/home`. Temporary files may be under `/tmp`. Installed programs may appear under `/usr`, `/bin`, `/sbin`, or `/opt`.

Knowing these locations helps you troubleshoot faster because you are not searching the whole machine blindly.

---

The Root Directory

The Linux filesystem starts at `/`.

Everything else lives under this root directory. There are no separate drive letters like `C:` or `D:`. Disks, devices, mounted filesystems, user directories, system folders, and application paths all appear somewhere inside the same tree.

This single-tree model is one reason Linux feels consistent across servers, containers, and cloud machines.

---

Important Directories

Some directories are worth recognizing early.

`/etc` stores system and service configuration. `/var` stores changing data such as logs, caches, queues, and application state. `/home` stores regular user directories. `/root` is the home directory for the root user. `/tmp` stores temporary files.

`/bin` and `/usr/bin` contain many commands. `/sbin` and `/usr/sbin` usually contain system administration commands. `/opt` is often used for optional or third-party software.

You do not need to memorize every directory today. The goal is to build a map in your head.

---

Virtual Filesystems

Some Linux directories do not behave like normal folders on disk.

`/proc` and `/sys` expose live system and kernel information. They look like files, but many of them are generated by the kernel while the system is running.

This is an important Linux idea: not every file is a normal saved document. Some files are interfaces into system state.

---

Why This Helps In DevOps

DevOps work often means diagnosing systems you did not build from scratch.

You may need to find where a service stores logs, inspect configuration, check whether a binary exists, or understand how an application has been installed. The filesystem hierarchy gives you a starting point.

It also helps when working with containers. Container images are usually Linux filesystems with only the files needed for an application. Understanding the normal Linux layout makes container images easier to inspect.

Takeaway:
The Linux filesystem is a map. When you understand the map, troubleshooting becomes calmer and faster.

## Interview Questions

### 1. What's the difference between /etc and /var directories?

/etc contains static system configuration files that don't change during operation (passwd, hosts, ssh config).
/var contains variable data that changes during system operation (logs, databases, cache, spool).
In short, /etc is for settings, /var is for runtime data. 

In DevOps, you modify /etc for configuration, monitor /var for logs and application state.

### 2. Explain the difference between /bin, /sbin, and /usr/bin.

/bin contains essential user commands needed for system boot and single-user mode (ls, cp, mv). 
/sbin has system administration commands requiring root privileges (fdisk, ifconfig, reboot). 
/usr/bin contains general user programs and applications. /

Remember, bin and /sbin are essential for system recovery, /usr/bin is for normal operations and might be on a separate filesystem.

### 3. Where would you find logs for troubleshooting a web server issue?

Check /var/log for system and application logs. Look for /var/log/apache2/ or /var/log/nginx/ for web server specific logs. 
Check /var/log/syslog or /var/log/messages for general system events. Also check /var/log/auth.log for authentication issues. 

Application logs might also be in their own directories under /var/log/ or in the application's directory structure.

### 4. What's the purpose of /proc and /sys directories?

/proc is a virtual filesystem providing process and kernel information (cpuinfo, meminfo, process directories).
/sys is for kernel and device information, used for configuring kernel parameters at runtime. Both exist only in memory, not on disk. /proc shows what's happening, /sys allows configuration. 

DevOps engineers use these for monitoring, tuning, and troubleshooting system performance.

### 5. Why does the root user have /root instead of /home/root?

Security and reliability. /root is separate from /home to ensure the root user can still log in if /home is on a separate filesystem that fails to mount. It's also a security boundary - regular users can't access /root even with read permissions on /home. 

This separation follows the principle of keeping critical system accounts isolated from user directories.
